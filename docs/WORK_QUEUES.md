# Очереди переноса и хеша

Диск движка не должен одновременно копировать пачку раздач и считать несколько
хешей. Лишняя работа ждёт.

| Очередь | Где считается | Лимит по умолчанию |
|---------|----------------|--------------------|
| Перенос с движка и на движок | API, на время копирования | 4 |
| Хеш на одном движке | движок, пока libtorrent в `checking` | 2 |

Перенос занимает слот **источника** и слот **приёмника**. С `a1` на `b1` идут
не больше четырёх копий сразу; пятая ждёт, даже если на `b2` свободно. Пока
идёт хеш после копии, слот переноса уже свободен — хеш стоит в своей очереди.

Хеш — кнопка «Перепроверить» и проверка в конце переноса. На движке сразу не
больше N таких проверок.

## Настройки

**Настройки → Лимиты → Очереди переноса и хеша.** Только admin.

`GET` и `POST /api/v1/settings/work-queues`

```json
{ "migrate_per_engine": 4, "hash_per_engine": 2 }
```

Диапазоны: перенос 1–16, хеш 1–8. Пустая запись в `app_settings` (`work_queues`)
берёт env `SEEDING_MIGRATE_PER_ENGINE` и `SEEDING_HASH_PER_ENGINE`.

Новый лимит переноса виден следующей задаче в очереди, без рестарта API.
Лимит хеша API сразу шлёт на движки (`POST /internal/v1/session/hash-limit`)
и повторяет при регистрации движка. Старый движок без этого метода отвечает
404 — настройка в БД всё равно сохраняется.
