# Очереди переноса и проверки

Диск движка не должен одновременно копировать пачку раздач и читать файлы
для нескольких проверок. Лишняя работа ждёт.

| Очередь | Где считается | Лимит по умолчанию |
|---------|----------------|--------------------|
| Перенос с движка и на движок | API, на время копирования | 4 |
| Проверка на одном движке | движок, пока идёт чтение файлов | 2 |

Перенос занимает слот **источника** и слот **приёмника**. С `a1` на `b1` идут
не больше четырёх копий сразу; пятая ждёт, даже если на `b2` свободно. Пока
идёт проверка после копии, слот переноса уже свободен — проверка стоит в своей
очереди.

Проверка — одно и то же чтение диска:

- волна после рестарта движка (`checking_files`);
- кнопка «Перепроверить»;
- хеш в конце переноса.

На движке сразу не больше N. `auto_managed` у раздач выключен, поэтому
`active_checking` libtorrent их не ограничивает: движок сам добавляет
раздачи из fastresume на паузе и снимает паузу только в свободный слот.

Сначала слот тратится на короткий resume, чтобы отличить готовый сид от
полного прохода. Сид отпускает слот сразу. Полный проход, если слотов уже
нет, снова встаёт на паузу и в карточке подписан «Ждёт проверки» — это не
пауза пользователя. Ручная пауза пишется в `.state/user-paused.json` и
очередь её не снимает. Когда непроверенных не осталось, полные проходы
идут по N и не мешают друг другу по диску.

## Настройки

**Настройки → Лимиты → Очереди переноса и проверки.** Только admin.

`GET` и `POST /api/v1/settings/work-queues`

```json
{ "migrate_per_engine": 4, "hash_per_engine": 2 }
```

Диапазоны: перенос 1–16, проверка 1–8. Пустая запись в `app_settings` (`work_queues`)
берёт env `SEEDING_MIGRATE_PER_ENGINE` и `SEEDING_HASH_PER_ENGINE`.

Новый лимит переноса виден следующей задаче в очереди, без рестарта API.
Лимит проверки API сразу шлёт на движки (`POST /internal/v1/session/hash-limit`)
и повторяет при регистрации движка. Поле в JSON по-прежнему `hash_per_engine`.
Старый движок без этого метода отвечает 404 — настройка в БД всё равно
сохраняется. Очередь на волну после рестарта есть только у движка 1.6.8 и новее.
