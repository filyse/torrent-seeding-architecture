# Кабинет (`/cabinet`)

Тонкая страница «я и привычки», не банковский личный кабинет.
Админка (лимиты, бэкапы, ключи, здоровье, весь журнал) остаётся в **Настройки**.
Меню в шапке — вход на эту страницу, выход и смена учётки; **на самом `/cabinet`
его нет** (дубль карточки «Профиль»). Чипа движков 9/9 в шапке кабинета тоже нет.

Макет — вариант **В** из обсуждения: профиль, привычки браузера, этот вход,
чужие сессии, свои строки аудита.

## Что на странице

| Блок | Откуда данные | Кому |
|------|----------------|------|
| Профиль (имя, роль, аватар, пароль, смена учётки, выход) | `/auth/me`, уже существующие диалоги | все; пароль — только вход по логину |
| Тема, вид списка, строк на странице, открывать список, метка при добавлении, период графиков | `localStorage` (`ui.theme`, `ui.view`, `ui.density`, `ui.pageSize`, `ui.openLabel`, `ui.openEngine`, `ui.addLabel`, `ui.historyPeriod`) | все |
| Этот вход (как вошли, последний вход, срок этой сессии) | `/auth/me` | все; срок — только сессия |
| Сессии + «выйти на всех, кроме этого» (красные кнопки) | `/auth/me/sessions` | только логин/пароль |
| Мои последние действия | `/auth/me/audit` | все (только свои строки) |

В таблице сессий **нет** браузера и IP: в `user_sessions` этого нет, колонки
не заводим. Показываем «этот» / «другая», даты создания, активности и истечения.

Аватар и пароль правятся только здесь, не из меню шапки. Настройки → Пользователи показывают
тот же `users.avatar` кружком слева от имени, без смены. У ключей аватара нет.

Не кладём сюда: уведомления фермы, здоровье, лимиты, ключи, бэкапы, почту, 2FA.

Тема уезжает с Настройки → Информация сюда — иначе снова дубль, как с «Аккаунт».

## API

- `GET /auth/me` — плюс `last_login_at`, `expires_at` (текущая сессия или `null`).
- `GET /auth/me/sessions` — список своих сессий, флаг `current`.
- `DELETE /auth/me/sessions/{id}` — погасить чужую; текущую этим путём нельзя.
- `POST /auth/me/sessions/revoke-others` — погасить все, кроме текущей.
- `GET /auth/me/audit?limit=` — свои строки из того же журнала, что `/audit` у admin.

Сессии и смена пароля — `require_identity`, вход по логину. Ключ API кабинет
открывает, но блоки сессий/пароля скрыты.

Новой схемы БД нет: таблицы `user_sessions` и `audit_log` уже пишутся.

Версии: web **1.52.4**, api **1.19.0**. Вид списка в привычках — четыре сегмента
(плитка / карточки / мини таблица / таблица), см. [`LIST_TILES.md`](LIST_TILES.md).
«Открывать список» — метка и движок для холодного старта и для «Сбросить всё».
Текущие `ui.label` / `ui.engine` при смене этих селектов тоже переписываются,
чтобы «Назад к списку» сразу показал выбранное. Временный фильтр в тулбаре
не затирается при каждом заходе на список.

## Откат

Точка до фичи: `fd704cf` (только спека).

1. `git log --oneline -10` — коммит `feat: add /cabinet page`.
2. `git revert <хеш>` на `main`, push.
3. На CT400: `git fetch && git reset --hard origin/main` и
   `bash scripts/deploy-ct400.sh up -d --build api web`.

Движки не пересобирать. После отката `/cabinet` снова станет списком раздач
(как любой неизвестный путь); пункт меню пропадёт; тема вернётся в Настройки.
Сессии в БД не чистим — они и раньше жили без экрана.
