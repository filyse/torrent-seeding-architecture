# Ручные сценарии (веб + десктоп)

Используйте при приёмке релиза или перед PR, затем кратко занесите результат в `docs/reports/YYYY-MM-DD-qa-agent9.md`.

**Автоматически (без браузера):** из корня проекта `pip install -e "./db[dev]" -e "./api[test]" -e "./engine" && pytest`; фронт: `cd web && npm install && npm run build`. Ожидание pytest: 18 passed, 3 skipped (без compose-интеграции).

## Предусловия

- Подняты **API** и **engine** (например `docker compose up` или локально uvicorn).
- База с миграциями / `SEEDING_AUTO_SCHEMA` для dev.

## Веб (`web/`)

- [ ] Открыть UI (Docker `:3000` или `npm run dev`).
- [ ] Список торрентов загружается без ошибки в красной строке статуса.
- [ ] Добавить magnet + `save_path` — запись появляется в таблице, статус обновляется.
- [ ] Пауза / старт для строки — статус и при необходимости `runtime` меняются.
- [ ] **Удалить** торрент — строка исчезает из списка; в движке торрент снят (проверка через детали/логи при необходимости).
- [ ] Клик по **id** — страница деталей, JSON с полем `runtime` (или `null`, если движок недоступен).
- [ ] «К списку» / hash `#/` — возврат к списку.
- [ ] Фильтры → Состояние: есть **Переносящиеся**; счётчик совпадает с
      `GET /api/v1/torrents/facets` → `states.migrating`; выбор показывает только
      раздачи в переносе (`status=migrating`).
- [ ] После остановки API проверить понятное сообщение об ошибке сети (не пустой экран).

### Экран «Сеть» (отдача, скачивание, всего отдано, история)

- [ ] Клик по карточке **«Отдача»** в верхней панели открывает `/network`.
- [ ] Клик по **«Скачивание»** открывает `/network/download`; вкладки переключают сторону.
- [ ] Клик по **«Всего отдано»** открывает `/network/uploaded`; крупная цифра — байты,
      не скорость; шкалы «% канала» нет, есть доля от общего объёма.
- [ ] Сумма карточек WAN на «Всего отдано» совпадает с чипом в шапке (не с колонкой
      «Отдано» в списке — там накопитель БД).
- [ ] Показаны карточки каналов; сумма движков в них покрывает все движки из `/engines`
      (лишние попадают в карточку «Вне карты» — её быть не должно).
- [ ] Скорости и объёмы обновляются вживую, без перезагрузки страницы.
- [ ] Утилизация правдоподобна: при отдаче ~125 МБ/с шкала показывает ~100% от 1 Гбит
      (частая ошибка — забыть множитель ×8 между байтами/с и битами/с).
- [ ] Остановленный движок отображается как «офлайн» и не ломает суммы канала.
- [ ] Перезагрузка страницы (F5) на `/network`, `/network/download`, `/network/uploaded`
      и `/network/history` не даёт 404.
- [ ] Пока идёт заливка через меню «Файл», чип «Скачивание» и карточка нужного WAN
      растут на скорость очереди; в строке движка видно «файлы …». На «Всего отдано»
      заливка не прибавляется.
- [ ] На `/network/uploaded` верхние карточки без графика (как до графиков:
      цифра, доля, движки). Под сеткой отдельная рамка с мини-графиком
      каждого канала. Наведение на столбик — интервал, объём, доля, движки.
- [ ] Вкладка **«История»** открывает `/network/history`: стек WAN1+WAN2 и сегменты
      День / Неделя / Месяц. Столбик — объём за корзину, не бегущая сумма и не колонка
      «Отдано» в списке. Пока мало сэмплов — график короткий. Сетка карточек WAN
      на этой вкладке не показывается.
- [ ] `GET /api/v1/network/uploaded-history?period=week` отдаёт `buckets` с дельтами
      и `previous_total`. Живой WS не перерисовывает SVG каждые несколько секунд.

### «Отдано» переживает перенос между движками

- [ ] Запомнить «Отдано» у раздачи с ненулевым объёмом, перенести её на другой движок.
- [ ] Сразу после завершения переноса значение НЕ обнулилось (проверять и в списке, и на
      детали — они читают разные пути в API).
- [ ] Через ~1–2 прохода снимка (`SEEDING_RUNTIME_SNAPSHOT_INTERVAL`, по умолчанию 10с)
      значение не «прыгнуло» и не задвоилось.
- [ ] Дальнейшая отдача на новом движке прибавляется к прежнему объёму, а не считается
      с нуля.
- [ ] Сортировка по «Отдано» согласована с показанными числами.

### Резервные копии (см. `docs/BACKUP.md`)

- [ ] Настройки → «Резервные копии БД»: строка свежести зелёная, возраст правдоподобный.
- [ ] Вторая строка показывает состояние движков и их количество (должно быть 9).
- [ ] «Создать сейчас» добавляет копию, список обновляется.
- [ ] Скачивание копии отдаёт файл, удаление убирает строку.
- [ ] Прогон `bash /opt/containerd/scripts/db-backup.sh` создаёт и дамп, и архивы в
      `_backups/db/engines/` (по одному на каждый движок).
- [ ] Остановленный движок не роняет весь бэкап: остальные архивы создаются, в логе
      предупреждение, `.partial` не остаётся.
- [ ] Искусственно состарить копии (`touch -d '3 days ago'`) — строка становится жёлтой
      с подсказкой про cron.

### Загрузка файлов (вшита в движок, см. `docs/FILE_UPLOAD.md`)

- [ ] Меню **Файл** видно operator/admin; у viewer пункта нет.
- [ ] Залить небольшой файл на **b1** (direct) — статус «готово», файл на диске движка.
- [ ] То же на **a1**.
- [ ] Обрыв и повтор — докачка с того же места, не с нуля.
- [ ] После заливки «Создать торрент» предлагает **каталог**, не файл.
- [ ] Admin: Настройки → Лимиты → «Загрузка файлов» — сохранить 1 и 2; очередь
      подхватывает без перезагрузки. Operator кнопку не видит / POST даёт 403.
- [ ] `curl :8090/internal/v1/…` с data-host — 404 от upload-edge, не ответ движка.

## Очередь создания и MPW

- [ ] «Создать торрент» → задача в очереди, статус `completed`, `.torrent` скачивается.
- [ ] «Удалить» в очереди web → в Kafka `creator.task.deleted` с `task_key` (`a1:0`);
      строка во вкладке Torrent MPW исчезает без опроса готовой очереди.
- [ ] Без `SEEDING_KAFKA_BOOTSTRAP` удаление на CT 400 всё равно проходит (пуш молчит).

## Десктоп CLI (`desktop/`)

```bash
pip install -e ./desktop
python -m seeding_desktop --api-base http://127.0.0.1:8000 list
python -m seeding_desktop --api-base http://127.0.0.1:8000 add --magnet "magnet:?xt=..." --save-path /data
python -m seeding_desktop --api-base http://127.0.0.1:8000 get 1
python -m seeding_desktop --api-base http://127.0.0.1:8000 pause 1
python -m seeding_desktop --api-base http://127.0.0.1:8000 resume 1
python -m seeding_desktop --api-base http://127.0.0.1:8000 remove 1
```

При включённых ключах API: добавьте `--api-key …`.

- [ ] `list` возвращает JSON-массив.
- [ ] `add` возвращает 201 и объект торрента.
- [ ] `get` / `pause` / `resume` отрабатывают для существующего id.
- [ ] При неверном URL — ненулевой код выхода и сообщение в stderr.
